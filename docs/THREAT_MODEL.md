# 威胁模型

> 这份文档写的是"我们防什么、怎么防、以及**我们不承诺防什么**"。最后一部分比前面更重要。

## 1. 资产

| 资产 | 泄露后果 |
| :-- | :-- |
| `PrivateVault`：卡点、反共识判断、隐性诉求（找联创/看机会）、屏蔽域名 | 职业风险（现雇主发现）、竞争情报、未发表想法被 scoop |
| `general_profiles.raw_fingerprint`：本人原始研究指纹 | 直接的身份反推 |
| 沙盒对话原文 | 通过技术细节反推身份；被截图外传 |
| `match_results`：对方对我的评分与理由 | 社交伤害、被"评分"羞辱 |
| 凭证（ORCID / 机构邮箱） | 身份冒用 |

## 2. 攻击者

| # | 攻击者 | 能力 | 动机 |
| :-- | :-- | :-- | :-- |
| A1 | 好奇/恶意的参会者 | 有自己的账号，能任意构造自述与 Pitch | 反推某位学者的身份、确认某人是否在看机会 |
| A2 | 投放垃圾信息者 | 批量注册、群发 Pitch | 招聘/推销/引流 |
| A3 | 恶意 agent 作者 | 控制自己 agent 的输入输出，可注入任意文本 | 操纵对方的 judge 打分、套取档案 |
| A4 | 被告知者（内部） | 能读数据库，但没有 KMS 密钥 | 窥探参会者私密诉求 |
| A5 | 抓包者 | 能读自己客户端的明文与网络流量 | 获得对方在沙盒里说的原话 |
| A6 | 平台运维 | 有全部权限 | 滥用（这是最难防的，只能靠审计与最小化） |

## 3. 防线与对应关系

| 攻击 | 防线 | 位置 |
| :-- | :-- | :-- |
| A1 通过卡片反推 | 卡片只含 k-匿名标签；披露守卫对卡片 prose 再核查一次同簇人数；身份在双向前完全不可见 | `domain/disclosure.py`、`services/cards.py:serialize` |
| A1 通过对方 agent 套话 | **人类不可触达 A2A 层**：API 没有返回原文的路由；prompt 明令禁止试探身份；每句出站文本过脱敏 | `api/routes_*`（无 transcript 路由）、`llm/prompts.py`、`domain/pii.py` |
| A1 通过同簇计数做交集攻击（多次查询缩小范围） | 卡片每日上限 3；每次披露都要求 cohort ≥ k，且 `cohort_size` 会随查询变化而被守卫重新计算 | `domain/budget.py`、`domain/disclosure.py` |
| A2 群发 | 门卫 Tier-3 关键词拦截 + 每目标每日最多 2 次 + Pitch 结构校验 + 公平槽位有限 | `domain/gatekeeper.py` |
| A3 注入操纵评分 | 沙盒无工具；输出限固定 JSON schema；peer 文本包在 `untrusted` 标签；指令形状内容一票中止；judge 只看对话记录，无法读取对方 prompt | `domain/sandbox.py`、`domain/pii.py:scan_injection`、`llm/prompts.py` |
| A3 通过证据句注入 | 证据句在进入卡片前重新过脱敏与注入扫描，异常则替换为确定性表述 | `domain/sandbox.py` |
| A4 数据库泄露 | vault 为 AES-GCM 密文，密钥不在库里；盲索引是不可逆 HMAC；沙盒原文根本没落库 | `core/security.py`、`db/models.py` |
| A5 抓包 | 跨 agent 的博弈全部发生在服务端封闭沙盒；客户端只能看到卡片与自己的判断结果 | `services/matching.py` |
| A6 运维滥用 | 所有沙盒场次落 `sandbox_sessions`（摘要 + 风险 + 成本）；`audit_events` 记录每次销毁；`PrivateVault` 的读取只发生在跑批进程内，且有 `vault_wiped` 事件 | `services/matching.py`、`api/routes_attendee.py:transparency` |

## 4. 我们不承诺什么（关键）

**k-匿名防不住对方亲口说出自己是谁。**
沙盒里的对话是技术性的。一个真正的行家会用"我们在 4 张 A100 上把尾延迟从 800ms 压到 520ms"这类描述，而这类描述在小圈子里是可识别的。我们能做的：

- 出站文本强制脱敏（机构、仓库、论文号、star 数、数字指标会被打码）；
- 证据句只能来自已核实的锚点或对话词元；
- 但**无法阻止**对方用"我知道的常识"暗示身份。

这是"匿名但有技术深度"的固有张力。产品承诺是"不让系统替你把身份泄露出去"，不是"保证对方永远猜不到你是谁"。UI 与文档里都这么写。

**评分机制的博弈。**
门卫与外部门的 Pitch 打分会被逆向优化——只要攻击者能反复试探阈值，就能写出"刚好过线"的模板。缓解手段是每次判定都返回 coarse reason code 而不返回分数分项、限流、以及公平槽位让"过线"不等于"被看到"。但这是一场持续的军备竞赛，不是一次性解决的问题。

**本地 Harness 一旦被污染。**
我们提供的是 MCP 桥（三个只读/写卡片工具，无 shell、无文件系统），但如果用户在自己的 harness 里把会议数据粘进一个有高权限的会话，风险就转移到用户侧。文档里明确说明：会议网络的接入必须运行在只读子会话里。

**推理成本侧信道。**
理论上，攻击者可以通过"某人的卡片多久出现"推测活动水平。缓解：每日固定时间批量交付（早 8 点），而不是实时推送。

## 5. 残余风险清单（交付时必须一起交）

1. 沙盒中的技术细节可能在小圈子内自我识别 → 需要会期人工抽检对话（不存储原文的限制下，抽检只能靠"证据句 + 风险标记"）。
2. judge 模型的口味偏差会系统性影响谁被解锁 → 需要定期用公开样本回归（见 RUNBOOK 校准节）。
3. 大规模并发下，SQLite 会先扛不住（写放大），必须切 PostgreSQL。
4. 部分强隐私诉求（例如"我在看机会，绝不能被我现在的同事看到"）依赖 `avoid_domains` 的完整性；域名写错的用户会失去保护。UI 需要提示"再核一遍域名"。
